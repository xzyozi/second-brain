## 1. ディレクトリ構成の完全設計
### 1.1 全体構造図
本システムは「母艦（システム管理用Git）」と「衛星（個別プロダクト用独立Git群）」に分離して運用する。

```text
~/second-brain/                        ← 【母艦】システム管理 Git ルート
├── .gitignore                         ← /projects/* を遮断する境界線
├── .gitattributes                     ← 全ファイル eol=lf 強制
├── AGENTS.md                          ← 【憲法】全エージェント絶対遵守ルール
├── roadmap.md                         ← 【台帳】全プロジェクト横断マイルストーン
├── opencode.json                      ← OpenCode設定
│
├── .opencode/                         
│   ├── agents/ (sisyphus, pm, orchestrator, executor, coder)
│   └── commands/ (new-proj, orchestrate, work, ask, status)
│
├── projects/                          ← 【衛星軌道】独立Gitリポジトリ群
│   ├── .project-registry.json         ← 全プロジェクトのパス・キー索引台帳
│   └── <project-a>/                   ← 【衛星A】独立Gitリポジトリ (.git保有)
│       ├── project.json               ← {"name": "...", "key": "PA"}
│       ├── README.md                  ← Why / MVP / 技術懸念
│       ├── tasks.md                   ← [PA-001] タスクリスト
│       └── src/                       ← 実装コード
│
├── tools/                             ← 決定論的 Python スクリプト群
│   ├── score-issues.py / check-blockers.py / update-roadmap.py / add-task.py / notify.py
│   └── .cache/                        ← 揮発性キャッシュ（Git非管理）
│
└── bin/                               ← 自動化シェル・エイリアス群

```

### 1.2 ディレクトリ別 Git管理方針

| ディレクトリ | Git管理 | 理由 |
| --- | --- | --- |
| **AGENTS.md / opencode.json** | ✅ 母艦で管理 | 設定変更履歴・行動規範の永続化 |
| **roadmap.md** | ✅ 母艦で管理 | 全社横断マイルストーンの監査証跡 |
| **.opencode/** | ✅ 母艦で管理 | エージェント・コマンド定義履歴 |
| **tools/*.py** | ✅ 母艦で管理 | スクリプト自体のバージョン管理 |
| **projects/.project-registry.json** | ✅ 母艦で管理 | 衛星プロジェクト台帳のインデックス |
| **projects/<name>/** | ⚠️ **各衛星自身で独立管理** | 母艦のGitからは `.gitignore` により完全隠蔽 |
| **tools/.cache/** | ❌ 管理外 | 日次再生成される一時キャッシュ |

## 2. Git 運用設計

### 2.1 ブランチ戦略

母艦および衛星ともにシンプルな2ブランチ構成を採用する。

* **main**：常に動作確認が取れた安定版。ドキュメントやタスクチェックボックスの直接更新のみ許可。
* **dev**：実装作業用。`coder` エージェントは必ず `dev` ブランチ上でコードを生成し、完了後に `main` へマージする。

### 2.2 コミットメッセージ規約

* `feat([KEY-N]): 新機能追加` （例: `feat([MOB-001]): 認証ログイン画面の実装`）
* `fix([KEY-N]): バグ修正`
* `docs([KEY-N]): ドキュメント更新`
* `roadmap: マイルストーン更新` （例: `roadmap: [MOB-001] done`）
* `task: タスク台帳チェック更新`
* `chore: ツール・設定微調整`

### 2.3 タスク完了からコミットまでの標準フロー

```bash
# ① coder が実装完了を報告し、以下を提案（自動実行はしない）
python3 tools/update-roadmap.py MOB-001 done --note "認証画面実装完了"
python3 tools/notify.py --event task_done --issue MOB-001 --title "ログイン画面実装"

# ② 人間がターミナルで確認し承認実行
$cd ~/second-brain/projects/mobile-app$ git add .
$ git commit -m "feat([MOB-001]): ログイン画面実装"

```

## 3. 日常操作フロー

### 3.1 朝のルーティン（毎日）

1. **07:00**：cronにより自動的に `score-issues.py` および `check-blockers.py` がバックグラウンド実行される。
2. **07:01**：Windowsデスクトップ右下にバルーン通知「本日の第1位: [MOB-002] スコア94.2」が届く。
3. **出社時**：ターミナルを開き `sb-plan` を実行。オーケストレーターが今日の実行計画表トップ3を提示する。
4. **着手**：人間が `/work MOB-002` を打ち込んで開発スタート。

### 3.2 新規プロジェクト立ち上げフロー

```text
> /new-proj my-next-app WEB
[pm] 新規プロジェクト「my-next-app (KEY: WEB)」を発足しました。
     質問1: このプロジェクトが解決する『誰のどんな痛み（Why）』を教えてください。
> 回答を入力...
（3問完了後、自動的に projects/my-next-app/ に README.md が生成され台帳に登録される）

```

## 4. CLI エイリアス早見表 (`bin/aliases.zsh`)

| コマンド | 意味 | 使用例 |
| --- | --- | --- |
| **`ocs "<指示>"`** | Sisyphusへ投げる（自動ルーティング） | `ocs "FXボットが止まる原因を調べて"` |
| **`ocp "<指示>"`** | PMペルソナへ直接投げる | `ocp "新機能の仕様を整理したい"` |
| **`oco "<指示>"`** | Orchestratorへ直接投げる | `oco "今の優先度トップ表を出して"` |
| **`ocx "<指示>"`** | Executorへ直接投げる | `ocx "MOB-003を実行して"` |
| **`ocb "<指示>"`** | Coderへ直接投げる | `ocb "ログインAPIをPythonで実装して"` |
| **`sb-plan`** | 今日の実行計画表を再生成して取得 | `sb-plan` |
| **`sb-score`** | スコアリング計算のみ手動強制再実行 | `sb-score` |
